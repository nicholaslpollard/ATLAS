## Root cause

The target diagnostic showed 54 ambiguous filing-date mappings. Most ambiguity was generated by instruments that are not the intended common-equity strategy security: preferred shares, warrants, rights, SPAC units, and an ETF. It also showed historical old/new ticker pairs that were simultaneously admitted.

Massive documents two semantics that make the v1 identity query incorrect for a tradable common-equity decision:

1. the All Tickers `active` filter means whether the ticker is actively traded **on the queried historical date**;
2. the endpoint supports a `type` filter, and `market=stocks` contains multiple security types rather than common stock only.

The v1 implementation queried both `active=true` and `active=false` and did not constrain security type. Therefore it intentionally mixed securities not tradable on the decision date with active securities and mixed non-common instruments into a common-equity identity decision.

This is a source-semantics defect at the identity-provider boundary, not a reason to lower a frozen sample gate or select replacement issuers.
