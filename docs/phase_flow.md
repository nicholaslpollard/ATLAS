# ATLAS Phase Execution Flow

**Normative development-flow contract. Last synchronized: 2026-08-26.**

## Core rule

`DEFINE -> LOCK -> IMPLEMENT COHERENT BATCH -> FOCUSED TEST -> INDEPENDENT VALIDATE -> FULL REGRESSION/CI AT EVIDENCE BOUNDARY -> TARGET EVIDENCE IF REQUIRED -> DOCUMENT -> ACCEPT -> MERGE -> NEXT PHASE`

Use the largest safe coherent batch. No credential, endpoint, local artifact, connected account, passing test, or prior success silently expands provider, broker, support, automation, or LIVE authority.

## Research batching

When adjacent research gates are local/read-only and their methodology can be frozen together, implement and validate them cumulatively rather than forcing repeated operator handoffs. Negative results continue through the preregistered batch; zero selection or zero finalists are evidence, not software failure.

Before performance inspection, freeze search space, costs, dependence handling, multiplicity, chronology/purge, robustness checks, and protected-evidence boundary. Losing alternatives are not revived after internal/protected results without a new preregistered phase.

## Validation ladder

1. compile/static checks;
2. focused unit/contract tests;
3. independent validator;
4. full regression at the evidence boundary;
5. Ubuntu + Windows CI;
6. target-machine/provider evidence only when mocks/CI cannot establish the required fact;
7. reconciliation for real mutation or authority-changing work.

Read-only provider operations may use an explicit CLI subcommand as the authorization boundary when the phase contract says so. Mutations, execution, destructive cleanup, and LIVE retain stronger confirmation boundaries. Unknown/uncertain mutation state fails closed and requires reconciliation before retry.

## Acceptance

A phase is ACCEPTED only when required implementation, tests, independent validation, full CI, target evidence, negative paths, and documentation are complete. Merge the exact tested/documented head, verify authoritative `main`, synchronize living docs, then define the next numbered phase.
