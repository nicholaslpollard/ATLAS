## Implementation
`packages/data/marketdata_candidate_expansion_v1.py` and `scripts/run_marketdata_candidate_expansion_v1.py` compose already accepted native stock exporter, shared-chain planner and immutable chain cache, without modifying old provider receipts. First execution loads accepted DEVELOPMENT inputs, SHA-verifies native raw stock opens and writes immutable D:-bound bundle, opportunity manifest, chain plan and a per-year/per-month binding. Later executions verify and reuse that exact source/plan instead of repeatedly loading the 546 native accepted source units. All requests maintain original PIT previous-session date, explicit 28–60d monthly expiry, +/-8% raw-open strike query (capped to 25% merge), raw-as-traded basis and matching source SHA.

One invocation can issue at most 50 new requests, internally respecting the existing ten-new-GET cache limit per batch. It requires the external secondary research storage and 120 GiB candidate-cache quota, paid Starter, current workstation/private-use flags and a bounded observed credit budget (maximum 100). Original cache reserves 8 MiB per new request, inspects reported credits and physical free space, and durable intent precedes every potentially billed GET. Every request is identity-deduplicated, writes exact original raw response and SHA-bound receipt. Provider retries are disabled. If the user opts into `--classify-exact-no-data`, the only automatic offline continuation is a verified original HTTP 404, `s=no_data`, zero-credit receipt, intact original intent and exact query; a new sidecar is written without altering original raw or making a second API call. Any other quarantine, timeout, ambiguous response, credit/header/identity mismatch or unresolved attempt stops without replay. Per-plan run reports record safe progress, observed credits and remaining requests. Source-only evidence is physically on D:; ATLAS stock corpus and simulator stay on C:.
